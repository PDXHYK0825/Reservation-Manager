# 签到与违约模块

## 文件及依赖

- `managers/AttendanceViolationManager.h`
- `managers/AttendanceViolationManager.cpp`

本模块使用 C++17，实现签到、违约登记、违约撤销和查询。页面由界面模块接入。

公共依赖沿用项目计划中的定义：

| 文件 | 使用内容 |
| --- | --- |
| `common/Models.h` | `User`、`Reservation`、`Violation`、`AppData`、`OperationResult` 及对应枚举 |
| `common/Rules.h` | `QDateTime toMinute(const QDateTime& value)` |
| `storage/JsonStore.h` | `data()`、`commit()` |

需要 Qt Core 提供的字符串、日期时间、容器和 UUID 类型，不使用窗口控件。

## 类的组织

`AttendanceViolationManager.h` 声明类，`AttendanceViolationManager.cpp` 实现成员函数。四个公开接口与项目计划保持一致，内部使用普通循环、条件判断和明确类型的局部变量。

| 写法 | 课件中的对应内容 |
| --- | --- |
| `public` 声明对外接口，`private` 保存成员和查找函数 | 第三讲第7、8页：封装、访问控制和成员函数 |
| 使用 `AttendanceViolationManager::函数名` 在类外实现 | 第三讲第8页：类外定义成员函数 |
| 通过 `JsonStore &dataStore` 引用同一个保存对象 | 第三讲第12页：引用变量访问对象成员 |
| 构造函数用初始化列表设置引用成员 | 第六讲第39页：构造函数初始化列表示例 |
| 用 `#ifndef`、`#define`、`#endif` 防止头文件重复包含 | 第六讲第38页：Qt类头文件示例 |

类中没有申请动态内存，使用默认析构函数，不释放外部传入的保存对象。当前模块没有基类或多个派生实现，保持项目约定的普通类结构。

日期时间、容器、UUID及公共数据结构按项目接口使用；这四份课件没有逐项讲解这些API，接入时仍需结合公共模块理解。

## 调用方式

```cpp
AttendanceViolationManager manager(store);

OperationResult result = manager.checkIn(
    currentUser, reservationId, QDateTime::currentDateTime());

OperationResult added = manager.addViolation(
    currentAdmin, reservationId, QDateTime::currentDateTime());

OperationResult revoked = manager.revokeViolation(currentAdmin, violationId);

QVector<Violation> records = manager.listViolations(currentUser);
```

`store` 使用主程序已经加载的同一个 `JsonStore`，其生存期应覆盖管理器。用户对象来自登录结果。查询得到的是副本；撤销和签到均通过记录编号定位。

## 规则

- 学生仅能对本人的有效预约签到，时间范围为 `[startTime, endTime)`，禁止重复签到。
- 操作时间通过公共 `toMinute()` 归一化；无效时间返回失败。
- 管理员可以对已经开始的预约登记违约。同一预约最多有一条未撤销违约。
- 预约仍有效且未结束时，登记违约同时设置 `Terminated` 和 `closedAt`。
- 对已取消、已结束或已终止的预约补记违约，保留原预约状态和关闭时间。
- 取消和终止后仍保留 `checkedInAt`。撤销违约不恢复预约，已撤销记录仍可查询。
- 学生只查询本人记录，管理员查询全部记录。无效角色或空账号返回空列表。
- 每次修改只调用一次 `commit()`。提交失败原样返回保存错误，不直接修改共享数据，不自行刷新页面。

## 接入说明

将两个管理器文件加入工程，包含头文件后使用共享保存对象创建管理器。页面根据 `OperationResult.ok` 判断结果，通过 `message` 展示提示；刷新仍由主窗口统一处理 `JsonStore::dataChanged()`。

当前主分支只有空文件骨架。公共数据结构、`toMinute()` 和 `JsonStore` 需要由对应成员按项目计划完成后，才能进行整个桌面程序的编译和联调。

## 验证情况

公开接口已与任务文档逐项核对。本地完成35项业务隔离检查，覆盖权限、签到时间边界、重复操作、违约终止、撤销、查询范围和提交失败。隔离检查使用临时类型及保存对象替身，未验证真实 Qt 类型、JSON 文件保存或主程序。

Windows 联调时使用团队统一的 VS2022、C++17 和 Qt MSVC x64 版本，公共依赖补齐后再确认：

1. 两个管理器文件能在实际工程中编译和链接。
2. 通过真实登录对象调用接口，学生与管理员权限正确。
3. 11:00—11:30的预约在11:07签到成功，11:30签到失败。
4. 登记违约后，预约终止，签到时间保留；撤销后预约仍为终止状态。
5. 保存失败时不出现半完成记录；保存成功后重启，记录能够恢复。
